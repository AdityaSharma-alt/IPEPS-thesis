# iPEPS for the Transverse-Field Ising Model

Code, data, and figures for the thesis **"Strong correlations, entanglement and
quantum phases"** (Aditya Sharma, BITS Pilani Goa Campus, submitted to
Professor Rudranil Basu, 2026). The thesis studies the transverse-field Ising
model (TFIM),

$$H = -J \sum_{\langle ij \rangle} \sigma^z_i \sigma^z_j \;-\; h \sum_i \sigma^x_i ,$$

first as a 1D chain via DMRG (benchmarking the quantum phase transition
against the exact free-fermion solution), then as the genuinely
two-dimensional square-lattice problem via **infinite Projected
Entangled-Pair States (iPEPS)** with a GPU-accelerated Simple Update / Full
Update / CTMRG pipeline. The square-lattice critical point is at
**h꜀/J ≈ 3.04438(2)** (Blöte & Deng 2002), the benchmark used throughout.

This repository holds the GPU production code, the raw sweep data, the
plotting scripts, and the resulting figures for the 2D iPEPS chapter
(Chapter 7 of the thesis), plus the standalone diagnostic figures for the 1D
DMRG chain (Chapter 3).

## Production runs (Chapter 7)

Four sweeps were run on a campus GPU cluster and are reproduced end to end by
the scripts and data in this repository (`analysis/data/` holds SU-A, SU-B,
and FU-A; the D=6, χ=40 warm-chained FU-B run referenced in the thesis text
was produced by a similar but separate script not included in this archive).

## Headline results

- **Energy**: all iPEPS runs agree with the QMC reference to ~1–3.5% across
  the phase diagram, with the smallest error (~0.9%) just below the critical
  point (h ≈ 2.5). Full Update at D=4 matches Simple Update at D=12 to four
  decimal places at h꜀ — a 3× smaller bond dimension reaching the same
  accuracy by truncating with environment information instead of locally.
- **Counterintuitive χ-dependence**: increasing the CTMRG environment
  dimension χ at *fixed* D=12 pushes the apparent transition *further* from
  the true h꜀, because SU's own variational error (a state that is too
  ordered) and CTMRG's measurement error (an environment that under-counts
  long-range correlations) partially cancel at small χ; a larger χ exposes
  the underlying SU bias rather than fixing it (§7.8).
  **Fix:** increase D, or use Full Update — not a smaller χ.
  - `analysis/data/ipeps_tfim_D12_chi40.csv` — SU-A: apparent h꜀ ≈ 3.8
  - `analysis/data/ipeps_tfim_D12_chi60.csv` — SU-B: order persists to h ≈ 4.5
- **Entanglement structure**: at the same nominal D, FU states carry roughly
  10× the boundary entanglement entropy of SU states — SU truncates locally
  and under-populates the bond even when the energy looks similar.
- **FU benefit is small in absolute terms for the TFIM** (peak ΔE ≈ 8×10⁻³
  per site at D=4, near h꜀) — consistent with SU already being close to
  optimal for this unfrustrated model; FU should matter much more for
  frustrated models (Kagome Heisenberg, t-J, Hubbard).
- **1D DMRG benchmark** (Chapter 3): energy converges to the exact
  free-fermion result to ≲2.6×10⁻⁷; the order parameter reproduces the exact
  exponent β = 1/8; the critical entanglement entropy grows as S = (c/6)ln L
  with c ≈ 0.52, consistent with the exact (1+1)D Ising value c = 1/2.

See §7.8 of the thesis for the full discussion, and the four architectural
limitations (single-GPU FU memory cap at D≤8/χ≤60, sequential CTMRG, fixed
2×2 unit cell, imaginary-time only).

## Reproducing the figures

```bash
# Regenerate Chapter 7 figures from the bundled CSVs (no GPU needed)
cd analysis
pip install pandas matplotlib scipy
python plot_su.py      # -> ../figures/ch7_ipeps_square_lattice/fig{1,2,3}_su_*.png
python plot_ipeps.py   # -> ../figures/ch7_ipeps_square_lattice/fig{1,2,3}_*.png
```

Re-running the GPU sweeps themselves requires a CUDA GPU with `CUDA.jl` /
`cuTENSOR` / `TensorOperations.jl` installed:

```bash
julia --project=. scripts/benchmarks.jl          # SU-A: D=12, χ=40  (needs ~45-55 GiB, H100-class)
julia --project=. scripts/benchmarks_chi60.jl    # SU-B: D=12, χ=60
julia --project=. scripts/fu_sweep.jl            # FU-A: D=4,  χ=20  (fits a V100)
```

The `scripts/slurm/*.sbatch` files are the actual job scripts used on the
production cluster (paths updated here to match this repo's layout: run
`sbatch scripts/slurm/sweep_D12_chi40.sbatch` from the repo root).

## Algorithm summary

Each h-point runs the pipeline `Simple Update → double layer + CTMRG →
observables`, and for the FU runs, an additional `→ Full Update (ALS) →
CTMRG` stage before re-measuring:

- **iPEPS**: 2×2 unit cell (sites A, B, C, D), each a rank-5 tensor with legs
  ordered `(phys, up, right, down, left)`, physical dimension d=2, bond
  dimension D.
- **Simple Update**: imaginary-time TEBD, `exp(-δτ h_bond)` applied
  bond-by-bond (AB → CD → AC → BD) with diagonal bond-weight environments,
  under a monotonically decreasing δτ-schedule.
- **CTMRG**: directional sweep LEFT → UP → RIGHT → DOWN; each move forms an
  enlarged corner, SVDs a χD²×χD² matrix on GPU (`cuSOLVER.gesvdj!`), and
  truncates back to χ. Converges when the ℓ²-distance between successive
  normalized singular-value spectra of the corner drops below the tolerance.
- **Full Update**: for each bond, QR-split the two adjacent tensors into a
  passive part and an active part, apply the gate to the active parts, then
  solve `N·A′ = W` by Alternating Least Squares — `N` from the converged CTM
  environment (hole construction), `W` from the overlap with the exact
  evolved tensor. A sweep is accepted only if it lowers the energy within
  tolerance; otherwise the pre-sweep tensors are restored.
- A small explicit longitudinal field is mixed into the Trotter gate
  (`ε = 1e-3`) to pin the Z₂-symmetric ground state to a single branch,
  avoiding random-sign noise in ⟨σᶻ⟩ across an h-sweep.

See `CHANGES.md` for the memory-hygiene work (GPU buffer lifetime, why the
D=12/χ=40 double-layer tensors alone are 27.5 GB resident) that made the
production runs feasible on a single GPU.

## Legacy prototype

`ipeps_2x2 (1).jl` at the repository root is an earlier CPU-only prototype
(Julia + `TensorOperations.jl`, D = 2, 3, 4 with `auto_params(D)` memory
tuning) that predates the GPU production code in `src/`. It is kept for
reference; the physics and numerics it implements are superseded by
`src/ipeps_tfim_gpu.jl` and `src/ipeps_fu.jl`, which is what the thesis
results in this repository were generated with.
